# 提案：家庭日程移动端体验与标记优化

## 背景与动机（Why）

「家庭日程」上线后投入实际使用（保良局何壽南小學小一家长场景），暴露出若干体验问题：

1. **入口不顺手**：网站默认进入「房产看板」，但日常高频访问的是家庭日程，每次都要手动切换。
2. **手机端日历错位**：在窄屏手机上，日历最后一行（如 21–27）与下方分类图例重叠，「学校」徽章被长标题挤压变形，可读性差。根因是日历组件 `calendar.tsx` 使用了 Tailwind v4 语法（`size-(--cell-size)`、`[--cell-size:--spacing(8)]`），而本项目实际是 Tailwind v3.4，这些类名不编译，导致日期格尺寸失效。
3. **假期不易识别**：学校假期与普通校历事件同为蓝色「学校」标记，家长无法一眼区分哪天放假。
4. **分类配色相近**：「培训班」的 emerald 绿与假期浅绿接近，易混淆。
5. **查看当天安排路径长**：手机端「近期事件」排在「所选日期的安排」之前，点选某天后还要往下滚动才能看到当天详情。
6. **日历含其他年级专属事件**：日历定位是「小一」，但混入了小三 TSA、小六毕业营、中一派位等其他年级专属活动，造成干扰。

## 目标（What）

1. 将「家庭日程」设为网站默认首页（顶层视图默认 `family`），导航顺序家庭日程在前。
2. 修复手机端日历布局：日期格固定行高、等宽列，不再溢出或与图例重叠；分类徽章不被标题挤压变形。
3. 学校假期单独用**浅绿色**标记并在图例中体现（API 分类仍限三类，假期作为派生标记，按标题关键词识别）。
4. 「培训班」标记由绿色改为**紫色**，与假期浅绿区分。
5. 手机端将「所选日期的安排」与「近期事件」显示顺序对调（所选日期优先），桌面端保持原左右布局。
6. 清理日历中其他年级专属事件，使其聚焦「小一」。

## 非目标（Out of Scope）

- 不改动日程管理 API 的数据模型与分类枚举（仍为 `学校`/`培训班`/`其它`）。
- 不引入 Tailwind v4 升级；仅在使用层用 v3 兼容写法规避坏类。
- 不新增账号/权限、不做事件重复规则。

## 影响范围

- **前端**：
  - `src/App.tsx`：默认视图改为 `family`，导航顺序调整。
  - `src/sections/FamilySchedule.tsx`：日历布局覆盖（`classNames`）、自定义日期按钮、假期派生徽章与圆点、图例新增假期、事件区响应式 `order` 对调。
  - `src/types/schedule.ts`：新增假期识别与颜色常量；「培训班」配色改紫。
  - `src/data/family-events.ts`：兜底数据补充小一回校事件（与服务端一致）。
- **数据（服务端日历，经 API）**：删除其他年级专属事件，使日历聚焦小一。
- 不影响后端服务代码、爬虫与房产数据流。

## 验收标准（概要）

- 打开站点根路径默认展示家庭日程。
- iPhone 等窄屏上日历不溢出、不与图例重叠，徽章不变形。
- 学校假期显示为浅绿，「培训班」显示为紫色，图例含四种标记。
- 手机端点选日历某天后，当天安排显示在近期事件之前。
- 日历不再包含其他年级专属事件。
- 详细需求与场景见 `specs/family-schedule/spec.md`。

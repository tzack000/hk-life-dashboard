## Context

站点是 Vite 单页应用。`src/App.tsx` 用本地状态在「近期行程」「家庭日程」「房产看板」之间切换，三个区块保持挂载，避免筛选被重置。根路径打开时直接进入家庭日程。没有路由库，生产环境由 Nginx 托管静态文件。

## Goals / Non-Goals

**Goals:**

- 根路径展示首页，用入口卡跳到三个现有模块。
- 三个模块各自有可收藏的路径，顶栏可以回到首页。
- 子页面之间来回切换时，家庭日程的分类与日期、房产看板的筛选保持不变。

**Non-Goals:**

- 不改日程、行程、成交数据本身。
- 不重做三个模块内部的布局。
- 不引入新的路由依赖。

## Decisions

### 用 History API 做四条路径，不引入 react-router

路径固定为：

- `/` 首页
- `/family` 家庭日程
- `/trip` 近期行程
- `/property` 房产看板

点击站内链接时 `pushState`，浏览器后退走 `popstate`。未知路径用 `replaceState` 回到 `/`。

这样不用新增依赖，也和现有「三个视图保持挂载、用隐藏切换」的方式兼容：三个子页面始终挂载，只按当前路径显示其中一个；首页按路径显示。筛选状态因此不会在切换时丢失。

备选是安装 `react-router`。路径能力相同，但多一个依赖，而且默认会在离开路由时卸载页面，筛选状态要额外抬升。

### 首页只做入口，不内嵌三个模块

首页是站点说明加三张卡：家庭日程、近期行程、房产看板。行程卡可以带上即将出发的行程标题和倒计时，因为这份数据已经在前端。房产卡不在首页拉成交表，避免首页等待数据。

### 顶栏在所有页面都在

顺序为「首页」「家庭日程」「近期行程」「房产看板」。当前路径对应项为选中态。站点名称也链回 `/`。

### 生产环境需要 SPA 回退

直接打开 `/family` 时，Nginx 必须把不存在的路径回退到 `index.html`。Vite 开发服务器已经会这样做。部署时要确认站点配置包含 `try_files $uri $uri/ /index.html`。

## Risks / Trade-offs

- [直接访问子路径在未配置回退的 Nginx 上 404] → 部署前检查站点配置；开发环境不受影响。
- [三个子页面一直挂载，首页以外的数据请求在进站时就会发生] → 与现在打开站点就会挂载家庭日程和隐藏中的另两个视图相同，不增加新的请求面。
- [访问统计目前只在首次加载上报] → 路径变化时再上报一次，避免子页面访问被算成首页。

# 提案：新增家庭日程页面

## 背景与动机（Why）

当前「香港生活看板」聚焦房产租赁/成交价格展示，是一个面向决策的数据看板。但家庭日常生活中还有大量**需要家人共同关注的日历信息**散落在各处（学校通知群、微信、纸质通知单），缺少一个集中查看的入口，容易遗漏重要日期。

典型场景：
- 学校放假/开学/考试/家长日等校历安排
- 孩子的培训班 / 兴趣班 / 补习固定时间
- 家庭其它需要提醒的日期（缴费、体检、证件续期等）

希望在现有看板中**新增一个「家庭日程」页面**，让家人能一眼看到近期需要关注的日历信息。

## 目标（What）

1. 新增一个独立的「家庭日程」视图，可与现有「房产看板」切换。
2. 以**日历/列表**两种形式展示家庭日程事件。
3. 事件支持分类（学校 / 培训班 / 其它），不同分类有不同颜色标识。
4. 支持按分类筛选，并高亮「近期（未来 N 天内）」需关注的事件。
5. 提供一个**日程管理 API**（后端），支持事件的增删改查（CRUD），数据持久化到 SQLite，作为前端与 AI Agent 的统一数据源。
6. 提供一个**AI Agent SKILL**，让 Claude 等 AI 工具能够读取与维护家庭日历（查询近期事件、新增/修改/删除事件），方便家人用自然语言托管日程。

## 非目标（Out of Scope）

- 不做账号系统 / 多用户登录（API 用简单共享密钥保护写操作即可）。
- 不做推送通知 / 邮件提醒（仅页面内高亮）。
- 不接入第三方日历（Google Calendar / iCal）导入导出。
- 不做事件的递归/重复规则引擎（如每周循环的复杂 RRULE），本期固定/单次为主。

## 影响范围

- **前端**：新增类型、数据、页面 section、顶层导航切换；数据加载改为优先调用 API。
- **后端**：新增日程管理 API 服务（Flask + SQLite），参照现有 `analytics_server.py` 与 systemd 部署方式；Nginx 反代 `/api/schedule/*`。
- **AI 工具**：新增 `.claude/skills/family-calendar/SKILL.md`，封装通过 API 读写日历的操作约定。
- 复用现有 shadcn/ui 组件（calendar、card、badge、tabs、select）。
- 不影响现有爬虫与房产数据流。

## 验收标准（概要）

- 用户可在房产看板与家庭日程之间切换。
- 家庭日程页能正确按月展示事件，并区分分类颜色。
- 近期事件有明显高亮，并可按分类筛选。
- 日程管理 API 支持事件 CRUD，数据持久化，前端从 API 读取。
- AI Agent 能通过 SKILL 调用 API 查询与维护日历事件。
- 详细需求与场景见 `specs/family-schedule/spec.md`。
